## 3. 主机与业务地址速查

| 角色 | 地址 | 说明 |
|------|------|------|
| pfSense（主干侧） | `<PF_SENSE>` | L3；亦为对外端口转发入口 |
| pfSense DMZ 网关 | `<DMZ_GW>` | Agent 主机默认网关 |
| CornerstoneAgent | `<AGENT_HOST>` | Win10 IoT LTSC（DMZ） |
| 英特网 HTTP 代理 | `<HTTP_PROXY>:3128` | 安装/配置环境用（经公司代理出网） |
| 仪器工控机 | 见下表（L1） | 各机运行 Bridge TCP `54321` + Web/API `8080` |

### 3.1 二炼钢仪器（L1）

| 仪器 ID | 工控机名 / 序列 | IP | Cornerstone 远程选项（现场） | Agent 查环境/结果 |
|---------|-----------------|-----|------------------------------|-------------------|
| GC6 | GC6-663054J01 | `<GC6_IP>` | 具备 RQ 类查询 | ✅ Bridge `:8080` 可查 |
| GC7 | GC7-663057J01 | `<GC7_IP>` | 具备 RQ 类查询 | ✅ 工控机防火墙已放行 8080；可查 |
| GC8 | GC8-663142J01 | `<GC8_IP>` | 具备 RQ 类查询 | ✅ 当前默认 Agent 目标 |
| GO6 | GO6-663082J01 | `<GO6_IP>` | 许可界面多为 **RSL + NQ**；实测 RQ/RC 查询可用 | ✅ 可查环境参数 / Sets（与 GO7 同等对待） |
| GO7 | GO7-680914J01 | `<GO7_IP>` | **有 RC**（RC 覆盖 RQ） | ✅ 可查环境参数；Bridge 需兼容无 `ErrorCode` 应答 |
| GO9 | GO9-663142J02 | `<GO9_IP>` | 具备查询 | ✅ Bridge `:8080` 可查 |

LECO 选项对照（手册 Remote Access）：

| 选项 | 含义 | 与 Agent 关系 |
|------|------|----------------|
| **RQ** | Remote Query：只读查状态/参数/结果 | Agent P0 tools 依赖此能力（或等价） |
| **RSL** | Remote Sample Login：远程登样，本机仍控仪器 | **不能**替代 RQ 查环境参数 |
| **RC** | Remote Control：远程控机；**覆盖 RQ 只读查询** | 有 RC 即可支撑 Agent 只读采集 |

Agent 需访问每台仪器：

| 端口 | 协议 | 用途 |
|------|------|------|
| **8080** | TCP | Web + `/api/*`（Agent 主数据面） |
| **54321** | TCP | Bridge/CLI TCP 网关（连通性 / 排故） |

> 不要对 Agent 开放仪器机上的 Bridge 直绑 `8081`（若仅监听 `127.0.0.1`）；对外统一走 Web `8080`。

> **GO6**：许可键上可能看不到 RQ/RC，但现场实测仍可走 Bridge 做 `system-parameters` / `status-check` / `sets` 等查询——**不要因「仅 RSL」跳过 GO6**。  
> **GO7**：RC 已够用；若 REST 返回 `ErrorCode=`（空）但 `rawPreview` 有 XML，属 Bridge 解析过严（ONH 应答常无 `ErrorCode="0"`），与许可无关。

## 4. Agent → 仪器 Bridge/Web：防火墙如何配置

流量路径：**DMZ** `<AGENT_HOST>` → pfSense → **L1** `<L1_HOST>:8080/54321`。  
原则：只放行 Agent 到上述 6 台、仅两个端口；不要开整个 `<L1_NET>`。

```text
<AGENT_HOST> (Agent)
        │  TCP 8080 / 54321
        ▼
   pfSense DMZ→L1 规则
        │
        ▼
  <GC6_IP>/<GC7_IP>/<GC8_IP>/<GO6_IP>/<GO7_IP>/<GO9_IP>
  (GC6 GC7 GC8 GO6 GO7 GO9)
```

### 4.1 pfSense 别名（推荐）

**Firewall → Aliases**

| 别名名 | 类型 | 成员 |
|--------|------|------|
| `CornerstoneAgent` | Host(s) | `<AGENT_HOST>` |
| `CornerstoneInstruments` | Host(s) | `<GC6_IP>` `<GC7_IP>` `<GC8_IP>` `<GO6_IP>` `<GO7_IP>` `<GO9_IP>` |
| `CornerstoneDataPorts` | Port(s) | `8080` `54321` |

### 4.2 DMZ 接口出站规则

**Firewall → Rules → DMZ**，在默认拒绝之前新增：

| 字段 | 建议值 |
|------|--------|
| Action | **Pass** |
| Interface | **DMZ** |
| Protocol | **TCP** |
| Source | `CornerstoneAgent` |
| Destination | `CornerstoneInstruments` |
| Dest port | `CornerstoneDataPorts` |
| Description | `Agent → 仪器 Web:8080 / Bridge:54321` |
| State | 保持默认（建立状态表，回程自动放行） |

不要做：

- DMZ → L1 `any` / 全网段放行  
- 对 L3/互联网暴露仪器 `8080`/`54321`（仅 Agent 从 DMZ 访问）

### 4.3 路由与 NAT

- Agent 默认网关应为 `<DMZ_GW>`；`<L1_NET>` 经 pfSense 直连 L1，**一般无需静态路由**（pfSense 已持有 L1 接口网段）。
- DMZ↔L1 同机跨接口转发：**通常不做 SNAT**（保持源地址 `<AGENT_HOST>`，便于仪器侧审计）。若现网强制 NAT，需在仪器 Windows 防火墙中放行 NAT 后地址。

### 4.4 仪器工控机 Windows 防火墙（若仍不通）

各仪器机入站放行（源限 Agent）：

| 规则 | 端口 | 源 |
|------|------|-----|
| Cornerstone Web | TCP `8080` | `<AGENT_HOST>` |
| Cornerstone Bridge TCP | TCP `54321` | `<AGENT_HOST>` |

并确认 Bridge/Web 监听在 `0.0.0.0` 或该机 `<L1_HOST>`，而非仅 `127.0.0.1`。

### 4.5 验证（在 Agent `<AGENT_HOST>` 上）

```powershell
$ips = @('<GC6_IP>','<GC7_IP>','<GC8_IP>','<GO6_IP>','<GO7_IP>','<GO9_IP>')
foreach ($ip in $ips) {
  Write-Host "==== $ip ===="
  Test-NetConnection $ip -Port 8080  | Select-Object ComputerName, RemotePort, TcpTestSucceeded
  Test-NetConnection $ip -Port 54321 | Select-Object ComputerName, RemotePort, TcpTestSucceeded
}
# 任选一台测 HTTP
curl.exe -s -m 5 http://<GC8_IP>:8080/api/status
```

pfSense：**Status → System Logs → Firewall** 应见上述 Pass 命中；**Diagnostics → States** 可见 `<AGENT_HOST> → <L1_HOST>:8080/54321`。

### 4.6 与 Agent 配置的对应关系

每台仪器 Bridge 基址示例：`http://<GC8_IP>:8080`（GC8）。多仪器时在 Agent 注册表 / 配置中按 `instrument_id` 分别填写对应 IP，勿再误用主干地址 `<PF_SENSE>` 作为仪器数据面（该地址是 pfSense/转发入口，不是仪器机）。

## 5. 经代理访问英特网：防火墙应如何配置

Agent 主机在 **DMZ**，代理 `<HTTP_PROXY>:3128` 在公司代理网段，通常经 **L3 → 上游网关** 可达。目标是：**仅允许 Agent 访问该代理端口**，不要对英特网全面放行。

### 5.1 路由（先确认可达）

在 pfSense 上确认到 `<HTTP_PROXY>` 的下一跳走 L3 上游网关（默认路由即可则无需额外静态路由）。

在 Agent 主机上测试（配置代理前）：

```powershell
Test-NetConnection <HTTP_PROXY> -Port 3128
```

若失败，优先查：DMZ→L3 规则、NAT、上游是否放行 `<PF_SENSE>`（或 NAT 后源地址）访问 `<HTTP_PROXY>:3128`。

### 5.2 pfSense 防火墙规则（推荐）

在 **DMZ** 接口规则中新增（建议置顶于宽泛拒绝之前）：

| 字段 | 建议值 |
|------|--------|
| Action | **Pass** |
| Interface | **DMZ** |
| Protocol | **TCP** |
| Source | `<AGENT_HOST>`（或别名 `CornerstoneAgent`） |
| Destination | `<HTTP_PROXY>` |
| Dest port | **3128** |
| Description | `CornerstoneAgent → 公司 HTTP 代理` |

配套建议：

1. **不要**对 DMZ 开「任意目的 any/any」出站；英特网流量只走代理。
2. 若存在「DMZ → 阻断 RFC1918 / 阻断非 L1」类规则，需保证本条 **Pass** 优先，或把 `<HTTP_PROXY>` 加入例外。
3. **NAT**：DMZ 经 L3 出站时，确认 SNAT 为 `<PF_SENSE>`（或既定地址）。向代理管理员报备该源 IP，以便代理 ACL 放行。
4. **上游/公司侧**：主干或代理侧需允许 `<PF_SENSE>`（NAT 后）→ `<HTTP_PROXY>:3128`。仅改实验室 pfSense 不够时，需同步开上游。
5. **回程**：状态防火墙下 TCP 回程一般自动放行；勿在 L3 上误拦相关 established 会话。

可选加固：

| 规则方向 | 建议 |
|----------|------|
| DMZ → L1 | 见 **§4**（仅 6 台仪器的 `8080`/`54321`） |
| DMZ → L2 | 保持拒绝（本项目不用） |
| DMZ → 英特网直连 | 拒绝（除上述代理 3128） |
| L3/WAN → DMZ | 仅保留已有 RDP `9833`、SSH `4322` 端口转发 |

### 5.3 Windows（Agent 主机）代理设置

防火墙放通后，在 `<AGENT_HOST>` 上配置代理（二选一或同时）：

**系统代理（设置 → 网络和 Internet → 代理）**

- 地址：`<HTTP_PROXY>`
- 端口：`3128`

**当前用户环境变量（PowerShell，会话级）**

```powershell
$env:HTTP_PROXY  = "http://<HTTP_PROXY>:3128"
$env:HTTPS_PROXY = "http://<HTTP_PROXY>:3128"
$env:NO_PROXY    = "localhost,127.0.0.1,<GC6_IP>,<GC7_IP>,<GO6_IP>,<GO7_IP>,<GC8_IP>,<GO9_IP>,<DMZ_GW>,<AGENT_HOST>,<PF_SENSE>"
```

**机器级（安装服务/计划任务建议写入系统环境变量）**

```powershell
[Environment]::SetEnvironmentVariable("HTTP_PROXY",  "http://<HTTP_PROXY>:3128", "Machine")
[Environment]::SetEnvironmentVariable("HTTPS_PROXY", "http://<HTTP_PROXY>:3128", "Machine")
[Environment]::SetEnvironmentVariable("NO_PROXY",    "localhost,127.0.0.1,<GC6_IP>,<GC7_IP>,<GO6_IP>,<GO7_IP>,<GC8_IP>,<GO9_IP>,<DMZ_GW>,<AGENT_HOST>,<PF_SENSE>", "Machine")
```

说明：

- `pip`、多数安装器会读 `HTTP(S)_PROXY`；部分 GUI 安装器只认系统代理，两者都配更稳妥。
- **`NO_PROXY` 必配**：访问本机、DMZ、L1 仪器时不要走代理。Python `urllib` **不支持 CIDR**（如 `<L1_NET>`），请写明仪器 IP；`cornerstone_agent` 的 Bridge 客户端已强制直连、忽略代理。
- 若代理需认证，按公司规范配置（系统凭据或 `http://user:pass@<HTTP_PROXY>:3128`），密钥勿写入本仓库。

### 5.4 验证清单

1. pfSense：DMZ 规则命中计数增加；状态表可见 `<AGENT_HOST> → <HTTP_PROXY>:3128`。
2. 主机：`Test-NetConnection <HTTP_PROXY> -Port 3128` 成功。
3. 经代理拉包（示例）：

   ```powershell
   curl.exe -I --proxy http://<HTTP_PROXY>:3128 https://pypi.org
   ```

4. 确认 `NO_PROXY` 下访问 L1 Bridge（若已部署）不经代理。

## 6. SSH 免密访问（密钥登录）

运维入口：`ssh -p 4322 <用户名>@<PF_SENSE>` → pfSense 转发至 Agent `<AGENT_HOST>:22`。  
主机为 **Win10 IoT LTSC + OpenSSH Server**，免密 = 客户端私钥 + 服务端 `authorized_keys`。

### 6.1 前提

在 Agent 主机（管理员 PowerShell）确认 OpenSSH Server 已装并运行：

```powershell
Get-WindowsCapability -Online | Where-Object Name -like 'OpenSSH.Server*'
# 若 State 不是 Installed：
Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0

Start-Service sshd
Set-Service -Name sshd -StartupType Automatic
```

先用密码登录一次，确认端口转发正常：

```bash
ssh -p 4322 <用户名>@<PF_SENSE>
```

### 6.2 运维机（客户端）生成密钥

若尚无密钥（Linux / macOS / Windows 均可）：

```bash
ssh-keygen -t ed25519 -C "ops-cornerstone-agent" -f ~/.ssh/id_ed25519_csagent
```

按提示可设 passphrase（推荐）；私钥勿提交仓库、勿拷到仪器网无关机器。

### 6.3 把公钥放到 Agent 主机

先查看公钥内容：

```bash
cat ~/.ssh/id_ed25519_csagent.pub
```

**A. 登录用户属于 Administrators（Win10 常见）**

OpenSSH 默认把管理员公钥放在：

`C:\ProgramData\ssh\administrators_authorized_keys`

在 Agent 主机上（管理员 PowerShell），将上一行公钥追加写入该文件（可多行、多把公钥）：

```powershell
$pub = "ssh-ed25519 AAAA...你的公钥... ops-cornerstone-agent"
$dir = "C:\ProgramData\ssh"
New-Item -ItemType Directory -Force -Path $dir | Out-Null
Add-Content -Path "$dir\administrators_authorized_keys" -Value $pub -Encoding ascii
```

并收紧 ACL（否则 sshd 会忽略该文件）：

```powershell
$path = "C:\ProgramData\ssh\administrators_authorized_keys"
icacls $path /inheritance:r
icacls $path /grant "SYSTEM:(F)"
icacls $path /grant "Administrators:(F)"
Restart-Service sshd
```

**B. 普通（非管理员）用户**

公钥写入该用户目录：

`C:\Users\<用户名>\.ssh\authorized_keys`

```powershell
$user = $env:USERNAME   # 或目标用户名
$dir  = "C:\Users\$user\.ssh"
New-Item -ItemType Directory -Force -Path $dir | Out-Null
Add-Content -Path "$dir\authorized_keys" -Value $pub -Encoding ascii
icacls $dir /inheritance:r
icacls $dir /grant "${user}:(OI)(CI)F"
icacls $dir /grant "SYSTEM:(OI)(CI)F"
# authorized_keys 仅用户本人与 SYSTEM 可写/改
icacls "$dir\authorized_keys" /inheritance:r
icacls "$dir\authorized_keys" /grant "${user}:F"
icacls "$dir\authorized_keys" /grant "SYSTEM:F"
Restart-Service sshd
```

> 若希望管理员也走 `~\.ssh\authorized_keys`，可编辑 `C:\ProgramData\ssh\sshd_config`，注释掉 `Match Group administrators` 段中的 `AuthorizedKeysFile`，然后 `Restart-Service sshd`。未改配置时，管理员账号务必用方式 A。

### 6.4 客户端连接（免密）

```bash
ssh -i ~/.ssh/id_ed25519_csagent -p 4322 user@<PF_SENSE>
```

可选：写入客户端 `~/.ssh/config`：

```sshconfig
Host csagent-2lg
    HostName <PF_SENSE>
    Port 4322
    User user
    IdentityFile ~/.ssh/id_ed25519_csagent
    IdentitiesOnly yes
```

之后：`ssh csagent-2lg`。

从实验室 DMZ 内网直连时端口为 22：

```bash
ssh -i ~/.ssh/id_ed25519_csagent user@<AGENT_HOST>
```

**已配置（本机运维机）**：公钥已写入 Agent 的 `C:\ProgramData\ssh\administrators_authorized_keys`，可用上列命令免密登录。

### 6.5 建议加固（可选）

在 Agent 的 `C:\ProgramData\ssh\sshd_config` 中（确认免密可用后再改）：

```text
PubkeyAuthentication yes
PasswordAuthentication no
```

改完后 `Restart-Service sshd`。保留至少一把可用密钥与 RDP（`9833`）兜底，避免锁死。

### 6.6 常见问题

| 现象 | 处理 |
|------|------|
| 仍提示输入密码 | 确认用的是管理员则公钥在 `administrators_authorized_keys`；ACL 已按上收紧；`sshd` 已重启 |
| `Permission denied (publickey)` | `-i` 指向正确私钥；服务端公钥整行无断行/编码为 ASCII；用户名一致 |
| 本机可连、经 `4322` 不行 | 查 pfSense 端口转发与 Windows 防火墙入站「OpenSSH SSH Server」 |
| 密钥有 passphrase 每次都问 | 本机用 `ssh-agent` 加载私钥，或接受交互输入 passphrase（仍算免密登录服务端） |
